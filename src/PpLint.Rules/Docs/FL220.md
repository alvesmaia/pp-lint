# FL220 — Consulta sem filtro

## O que pega

Operação que lista registros — `GetItems` do SharePoint, `ListRecords` do Dataverse, `GetRows` do SQL — sem o parâmetro `$filter`.

A lista de operações é curta e nomeada, e cada entrada foi conferida no JSON de um fluxo real. Inventar nome de operação produziria regra que nunca dispara, ou que dispara no lugar errado.

## Por que importa

Sem `$filter`, a consulta traz tudo que couber na página e o recorte acontece depois, dentro do fluxo. Isso custa tráfego e tempo em toda execução.

Pior: o filtro do lado do fluxo só enxerga o que veio na página. Se o registro que interessa está na página seguinte, o fluxo conclui que ele não existe — sem erro, com a resposta errada.

## Exemplo

Ruim:

```json
"parameters": { "dataset": "...", "table": "Pedidos" }
```

Bom:

```json
"parameters": { "dataset": "...", "table": "Pedidos", "$filter": "Status eq 'Aberto'" }
```

No designer, é o campo "Filtrar consulta" nas opções avançadas da ação.
